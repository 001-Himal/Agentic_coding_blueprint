# Contributing to the Blueprint

1. Open an issue or discussion first for structural changes.
2. Keep files lean — the blueprint's power is in curation, not volume.
3. New systems need: a folder, a README explaining when to use it, and a mention in `.vibe/README.md` + root `README.md` tiers.
4. Bump BLUEPRINT-VERSION.md.
5. PRs: what/why/how-tested, per the PR template.
